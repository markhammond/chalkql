# ChalkQL 0.3

ChalkQL 0.3 adds composite values: a host function can answer a record that SQL takes apart by
field, an in-process table can hold a record as a column, and the host can read either back as its
own record type. Text stays bytes from the result batch to the delegate and the aggregate, DECIMAL
rounding agrees with the databases ChalkQL pushes work to, and floating-point rounding and casts are
exact. Some of this removes API or changes results; *Changed* lists every such change.

## Highlights

### Functions that answer a record

A client-bodied function may return a record. ChalkQL reads the record as the declaration of a
composite value — named fields, one level deep — whose fields are the record's public properties,
in the order a positional record declares them, each of a type a delegate may use (see below). SQL
reads a field by name:

```csharp
public readonly record struct Classification(Utf8String Category, double Confidence);

// The declaration, on the source.
.AddFunction("classify_transaction", f => f
    .Scalar<ReadOnlySpan<byte>, double, Classification>("description", "amount")
    .Strict()
    .Client())

// The implementation, in ChalkEngineOptions.Functions.
registry.AddScalar<ReadOnlySpan<byte>, double, Classification>(
    "classify_transaction", (description, amount) => classifier.Classify(description, amount));
```

```sql
SELECT id,
       classify_transaction(description, amount).category   AS category,
       classify_transaction(description, amount).confidence AS confidence
FROM transactions
WHERE classify_transaction(description, amount).confidence > 0.8
```

The engine checks the registered delegate's record against the declaration field by field when it
is created, and a mismatch names both sides. A field filters, orders and groups. The whole value can
be selected, named in a sub-query and expanded there with `s.c.*`, carried through `UNION ALL` and
an outer join, and tested with `IS NULL`; `CASE` and `COALESCE` choose between composites of one
type and `NULL`. Selected whole, it reaches the host as an Arrow struct column whose children are
named after the fields. An aggregate's `Finish` may answer a record too, grouped or over a window.
`ChalkType.Composite` and `CompositeField` declare a composite type explicitly, and
`ColumnWriter.Child` lets a Tier 2 kernel write one.

### Composite columns from in-process tables

A member of a POCO table, or of an `IndexedSet<T>` published through `AkadeSource`, whose type is a
record is a composite column, typed exactly as a function's record result is. `SELECT *` carries it
whole, `q.bid.price` reads one field, and each field is staged as a column of its own type would be,
so a scan allocates nothing per row beyond what those columns would. A record struct member is never
NULL, and its `Nullable<T>` may be; a record class member is nullable unless the compiler annotates
it as not null. Under entitlements the column is disclosed whole or withheld whole — `Full`, or
`None` with the NULL composite as its placeholder — and a rule's condition may read one of its
fields.

### Reading a composite back as a record

`GetComposite<T>`, `TryGetComposite<T>` and `ReadComposites<T>`, in `Chalk.Arrow`, read a struct
column — a function's composite or a composite column — as the host's own `T`: a record struct, a
record class, or a class with a parameterless constructor and settable properties, matched to the
fields by name, ignoring case. A field reads in any spelling a delegate parameter of its type could
take, so a DECIMAL(18, 2) reads into a `decimal` and a DATE into a `DateOnly`. The binding is built
on the first read of a given `T` and struct type and then cached; when it cannot work, that first
read is refused, naming both sides. `ReadComposites` sets the read up once for a run of rows:

```csharp
var classifications = new Classification?[batch.Length];
batch.Column(1).ReadComposites<Classification?>(classifications);   // null where the composite is NULL
```

`TryGetComposite` answers `false` for a NULL composite; `GetComposite` and `ReadComposites` answer
null into a class or a `Nullable<T>`, and refuse a NULL composite, naming the row, into any other
struct. Value fields are read from the batch's own buffers, so a record struct of value fields reads
without allocating. A `string`, `byte[]`, `Utf8String` or `ReadOnlyMemory<byte>` field is copied for
each row, because the record may outlive the batch. A DECIMAL field wider than 28 digits reads into
a `decimal` when the value fits, and is refused, naming the row, when it does not.

### Population-safe user aggregates

A population-only column's allow-list may name a user-defined aggregate, a composite-valued one
included, when its declaration says `.Population()`: the host's promise that the result reports the
group and never one row's value, every field of a composite result included. Like `.Leakproof()`,
the promise is recorded and relied on. The group-size floor guards such an aggregate as it guards
`COUNT`, and a group below the floor answers a NULL composite, whole. An allow-list that names a
user-defined aggregate without the declaration is refused, as in 0.2, and the message now says how
to declare one. The flag is `FunctionDescriptor.Population`, a new overload
`PopulationAggregates.IsPermitted(name, catalog)` asks a catalog, and a host that validates plans
itself passes `PlanValidationOptions.PopulationAggregates`.

### Delegates in the types a POCO property uses

A Tier 1 delegate may be written in the CLR types a POCO property maps from: `decimal` for a DECIMAL
of up to 28 digits, `DateOnly` for DATE, `TimeOnly` for TIME, `DateTime` for TIMESTAMP,
`DateTimeOffset` for TIMESTAMP_TZ (in UTC), `TimeSpan` for INTERVAL_DAY and `Guid` for UUID. Each
serves a parameter, a result, a composite field, a table function's argument or column, and a Tier 1
aggregate's input and result, and none of them allocates per row. `Parameter<T>()` and
`Returns<T>()` infer the SQL type as a POCO property would, `decimal` as DECIMAL(28, 10) and
`DateTime` as TIMESTAMP(9); a narrower type is declared with `Parameter(name, type)` and still
implemented in `decimal` or `DateTime`. A time the declared type cannot hold exactly, such as a
`TimeOnly` with a fraction of a microsecond, is refused rather than rounded, and a nanosecond
TIMESTAMP read as a `DateTime` is truncated to its 100-nanosecond tick. The raw counts 0.2 required,
`int` days and `long` units, still work.

### Text as bytes, from the batch to the delegate

`GetUtf8` on any Arrow string array — the view layout a STRING column arrives in by default, the
classic layout `ChalkEngineOptions.Output.Strings` asks for, or the large one — gives a cell as a
`ReadOnlySpan<byte>` over the batch's own buffer, with no copy and no decode. `TryGetUtf8` tells a
NULL apart, and `batch.GetUtf8(column, row)` reads a batch directly. The compiler keeps the span
inside the batch's lifetime, and `ToUtf8String()` copies one out to keep.
`Utf8StringComparer.ForString`, for keys of `string`, and `Utf8StringComparer.Ordinal`, for keys of
`Utf8String`, implement .NET's alternate-key contracts, so a `Dictionary`, `HashSet` or
`ConcurrentDictionary` looks a batch's bytes up with nothing allocated. `TextEquals` compares a span
with a `string` without making one, and `Utf8Hash` is the hash all three spellings share.

```csharp
var weights = new Dictionary<string, double>(Utf8StringComparer.ForString) { ["BTCUSDT"] = 0.4 };
var byBytes = weights.GetAlternateLookup<ReadOnlySpan<byte>>();

await foreach (var batch in execution.Batches)
{
    using (batch)
    {
        var symbols = batch.Column(0);
        for (var row = 0; row < batch.Length; row++)
        {
            if (byBytes.TryGetValue(symbols.GetUtf8(row), out var weight)) { /* no string made */ }
        }
    }
}
```

A Tier 1 delegate takes a STRING or BINARY argument the same way: a `ReadOnlySpan<byte>` over the
lane itself, lent for the call. It may answer a span too — a slice of its input, or of a buffer it
owns — which is copied into the result column before the next call and validated as UTF-8 where the
column is text. `ReadOnlySpan<byte>` infers as STRING, and a BINARY parameter spelled as a span is
declared explicitly. `string` and `byte[]` are the copying spellings, and allocate per row.

### Aggregates over text, and aggregates that keep data per group

A Tier 1 aggregate takes a STRING or BINARY input as a `ReadOnlySpan<byte>` over the value's own
bytes, with a fixed-width state and result, so a byte total, a prefix count or a hash over text is a
plain `AggregateSpec`. An aggregate that keeps variable-length data per group — the longest label, a
concatenation, a sketch, a bitmap — is the new `ArenaAggregateSpec`. Its state is still a struct;
what the struct cannot hold it rents from the `ArenaScope` every step receives, and it keeps
`ArenaHandle`s, an offset and a length each. A STRING or BINARY answer is a span over the scope,
copied into the result as each group is emitted, and `HasValue` makes a group NULL. The scope's
memory belongs to the execution and goes back when the operator releases it.

```csharp
public struct Longest
{
    public ArenaHandle Kept;
    public bool Any;
}

// Declared as .Aggregate<ReadOnlySpan<byte>, ReadOnlySpan<byte>>("label").Client().
registry.AddAggregate(
    "longest_label",
    new ArenaAggregateSpec<Longest, ReadOnlySpan<byte>, ReadOnlySpan<byte>>
    {
        Init = static (ref ArenaScope _) => default,
        Add = static (ref Longest s, ReadOnlySpan<byte> label, ref ArenaScope arena) =>
        {
            if (!s.Any || label.Length > s.Kept.Length)
            {
                s.Kept = arena.Keep(label);   // a copy, in memory the execution owns
                s.Any = true;
            }
        },
        HasValue = static (in Longest s) => s.Any,
        Finish = static (in Longest s, ref ArenaScope arena) => arena.Bytes(s.Kept),
    });
```

`ArenaAggregateSpec`, `ArenaScope` and the registry overload that takes one are experimental, under
the `CHALK001` diagnostic.

### A repeated expression is computed once

Within one step of a plan, an expression written more than once is compiled once and computed once
per batch: a call to an `Immutable()` or `Stable()` function, a built-in call, a `CAST`, a `CASE`,
an `IN` or a field access. The two fields of `classify_transaction` in the select list above cost
one classification per row, not two, and `CASE WHEN UPPER(name) = 'X' THEN UPPER(name) END`
computes `UPPER` once. A `WHERE` clause is a step of its own. Nothing that holds a `Volatile()` call
is shared, so a volatile function still runs once per occurrence.

### Refusals in the statement's own words

A composite value has no ordering and no equality, so sorting or grouping by one, comparing one,
`DISTINCT` or `CAST` over one, joining on one and passing one to a built-in aggregate are refused.
The refusal quotes what the statement wrote and suggests a field of the refused value itself.
Where `price_move` answers a record of `Direction` and `Change`, the statement's
`ORDER BY price_move("open", "close")` is refused as
`ORDER BY a composite value (price_move("open", "close"))`, with the example
`ORDER BY (price_move("open", "close")).Direction`. The planner likewise refuses `GROUP BY`,
`SELECT DISTINCT` and a `DISTINCT` aggregate over a LIST column, naming the clause and the column.

## Changed

This section lists what a 0.2 host may have to change, and every result that can differ.

### Removed and refused API

- `Chalk.ArrowUtf8Extensions` is removed, with its two `GetUtf8` extensions on `StringArray` and
  `StringViewArray`. Each returned a `Utf8String` borrowing the batch's buffer, a value that could
  be kept past the batch and read after the engine had reused the memory. Use `GetUtf8` in
  `Chalk.Arrow`, which takes any Arrow string array and returns a `ReadOnlySpan<byte>`, or
  `TryGetUtf8`; copy a value to keep with `ToUtf8String()`, or decode it with `GetUtf8String`.
  Where `Chalk.Arrow` is imported, a 0.2 call such as `array.GetUtf8(row).ToString()` still compiles
  and now calls `ReadOnlySpan<byte>.ToString()`, which does not decode the text; write
  `array.GetUtf8String(row)`.
- The Tier 2 `ColumnView` loses `Utf8(int)`, `Utf8View(int)`, `VarValueMemory(int)` and
  `Utf8ViewMemory(int)`, each of which handed a kernel a storable value over the batch's buffer.
  `VarValue(int)` gives the same bytes as a span for either string layout, and `Utf8ViewBytes(int)`
  for the view layout. The removed members were experimental (`CHALK001`).
- A Tier 1 delegate whose parameter is `Utf8String` or `Utf8String?` is refused when the engine is
  created, and the refusal names the spellings that replace it: `ReadOnlySpan<byte>`, which borrows
  the lane for the call, or `string`, which copies. A non-strict function spells a nullable STRING
  parameter `string?`, since a span has no NULL. The same holds of a Tier 1 aggregate's input. A
  result may still be a `Utf8String`, which is the host's own memory, and so may a POCO member or a
  composite field.
- `ReadOnlyMemory<byte>` is refused as a Tier 1 argument for the same reason; spell a BINARY
  argument `ReadOnlySpan<byte>` or `byte[]`. BINARY had no Tier 1 spelling in 0.2, and a result may
  be a `ReadOnlyMemory<byte>`.
- A Tier 1 aggregate whose state struct holds a reference — a `string`, an array, any object — is
  refused by `AddAggregate`, which throws `ArgumentException` naming the state type, because the
  state lives in arena memory, one per group. Keep the state to value fields, and keep
  variable-length data through an `ArenaAggregateSpec` and its `ArenaHandle`s.
- A Tier 1 aggregate with a STRING input spelled `string` or `Utf8String`, or with a STRING or
  BINARY result, is refused when the engine is created; in 0.2 it passed engine creation and failed
  at its first row. Spell the input `ReadOnlySpan<byte>`, and answer text from an
  `ArenaAggregateSpec`.
- `IFunctionRegistry` gains an `AddAggregate` overload that takes an
  `ArenaAggregateSpec<TState, TIn, TOut>`, and its type parameters now allow ref structs. A class
  that implements the interface itself must add the overload; the engine's own `FunctionRegistry`
  needs nothing.

```csharp
// 0.2
registry.AddScalar<Utf8String, long>("byte_length", s => s.Length);
Utf8String ticker = ((StringViewArray)batch.Column(0)).GetUtf8(row);

// 0.3
registry.AddScalar<ReadOnlySpan<byte>, long>("byte_length", s => s.Length);
ReadOnlySpan<byte> ticker = batch.Column(0).GetUtf8(row);
Utf8String kept = ticker.ToUtf8String();   // a copy, for a value that outlives the batch
```
- `TrustSourceRowSecurity()` on `AdoSourceBuilder` and `TrustSourceRowSecurity(bool)` on the Akade
  builders are renamed `TrustSourceRowLevelSecurity`, and each takes `RowLevelSecurityPreconditions`:
  the host asserts by name that every connection identifies the principal to the source, that
  row-level security is enabled and forced on every entitled table, and that the source's policies
  admit exactly the rows the entitlement would. A call that asserts fewer is refused, naming the
  ones it left out. The catalog's field is `trust_source_row_level_security`, the same number and
  type as before, so a recorded catalog reads as it did.
- `Zone(...)` on every source builder declares which sovereign zone a source's data belongs to, and a
  catalog whose sources declare two zones, or where some declare one and others none, is refused when
  the engine is created, naming the zones and the sources. A catalog is one zone; a host serving
  several runs one engine per zone and chooses per request. Nothing in planning reads the zone, and a
  catalog declaring none is unchanged.
- `PrepareOptions` is a record: compose a variant from a base with `with`. The entitled engine's own
  copy of the options is a `with` too, so every prepare option now reaches an entitled prepare; before,
  `IncludeRedactedSql`, `ParameterValueHints`, `Planning` and `RequireCurrentCatalog` were silently
  dropped on that path.

### Results that can differ

Every rescaling of a DECIMAL — a cast to a smaller scale, an arithmetic result at its declared
scale, a literal the catalog converts — rounded a midpoint half-even in 0.2. It rounds away from
zero in 0.3, as PostgreSQL, DuckDB, SQL Server and SQLite do, so a statement answers the same
wherever it ran; `ROUND` on a DECIMAL already rounded this way.

`ROUND` with a digit count on a DOUBLE or REAL rounded a scaled copy of the value, which is wrong
for about one input in twenty. It rounds the exact value the number holds, as `Math.Round` does
from .NET 11 on. The double written 655.925 is 655.92499999999995…, so it rounds down; the same
digits as a DECIMAL are exact, and `ROUND` of the DECIMAL 655.925 to two places is still 655.93.

A cast from DOUBLE or REAL to DECIMAL went through `System.Decimal`, which keeps fifteen
significant digits. It rounds the double's exact value, half away from zero, to the declared scale.
A cast from DECIMAL to DOUBLE or REAL is the correctly rounded value; 0.2's conversion could be one
unit in the last place off, and failed on a value wider than `System.Decimal` holds.

| Expression                   | Operand                           | 0.2                      | 0.3                      |
| ---------------------------- | --------------------------------- | ------------------------ | ------------------------ |
| `CAST(x AS DECIMAL(18, 2))`  | DECIMAL(18, 3) `0.125`            | `0.12`                   | `0.13`                   |
| `CAST(x AS DECIMAL(18, 2))`  | DECIMAL(18, 3) `-0.125`           | `-0.12`                  | `-0.13`                  |
| `ROUND(x, 2)`                | DOUBLE `655.925`                  | `655.93`                 | `655.92`                 |
| `ROUND(x, 2)`                | DOUBLE `2.675`                    | `2.68`                   | `2.67`                   |
| `CAST(x AS DECIMAL(18, 1))`  | DOUBLE `0.25`                     | `0.2`                    | `0.3`                    |
| `CAST(x AS DECIMAL(18, 1))`  | DOUBLE `0.35`                     | `0.4`                    | `0.3`                    |
| `CAST(x AS DECIMAL(38, 20))` | DOUBLE `0.1`                      | `0.10000000000000000000` | `0.10000000000000000555` |
| `CAST(x AS DOUBLE)`          | DECIMAL(38, 10) holding 38 digits | an error                 | the nearest double       |

### Other behaviour

- An expression written more than once within one step is computed once per batch, so a delegate
  that counts its calls sees fewer. The same call to an `Immutable()` or `Stable()` function written
  twice in one select list runs once per row, and a `Stable()` call of constants written several
  times runs once per execution. A `Volatile()` function runs once per occurrence, as before.
- `GROUP BY` or `SELECT DISTINCT` over a LIST column was refused in 0.2 by the client's plan
  validation, as an `InvalidPlanException`. The planner now refuses it first, as a
  `PlanningException` of kind `PlanErrorKind.Unsupported` that names the clause and the column.
  `COUNT(DISTINCT …)` over a LIST column, which 0.2 answered wrongly, is refused the same way.
  Plan validation, which in 0.2 refused a LIST only as a grouping or sort key, also refuses one as
  a join key, a window or session partition key, and an as-of join's time column.
- A non-strict delegate with a `string?` parameter is handed `null` for a NULL, where 0.2 handed it
  the empty string.
- `Utf8String.TextEquals` no longer matches a byte outside ASCII against a UTF-16 code unit of the
  same value (see *Fixed*).
- A POCO or Akade member whose type is a record, which 0.2 refused as having no mapping, is a
  composite column. A member left out with `Ignore` or `[ChalkIgnore]` stays out.
- The planner converts a statement through its own driver, a copy of Apache Calcite's `PlannerImpl`
  that never runs Calcite's structured-type flattener, which would split a composite-valued call
  into a call per field. Every plan the repository's corpus recorded under 0.2 re-records
  byte-identical, and the repository's `NOTICE` records the derived file.

## Fixed

- A relative `CHALK_PLANNER_JAR` or `PlannerProcessOptions.JarPath` was tried against the process's
  working directory alone, so a test host or a sample started beneath a checkout's root refused a
  value written from that root. It is searched for from the working directory upward and then from
  the application's directory upward, the nearest match winning, and the refusal names every
  directory tried.
- `COUNT(DISTINCT …)` over a LIST column counted every list as one, because the executor read a list
  as zero bytes wide. It is refused, naming the column.
- An as-of join whose time column was a LIST passed plan validation. It is refused.
- A non-strict delegate with a `string?` parameter was handed the empty string for a NULL. It is
  handed `null`.
- A Tier 1 aggregate declared over a STRING input passed engine creation and failed at its first
  row. It is refused when the engine is created, and the refusal names `ReadOnlySpan<byte>` as the
  spelling that works.
- `Utf8String.TextEquals` compared bytes with UTF-16 code units one for one when their counts were
  equal, so the bytes of `é` (`C3 A9`) equalled the string `"Ã©"`. A byte outside ASCII now never
  matches, and `TextEquals` on a span follows the same rule.
- A planning error that pointed at a user function call carried no usable position, because the
  casts the planner wraps round the call's arguments were built without one. The casts take their
  argument's position.
- The numeric fixes, to `ROUND` on a double or float and to the casts between DECIMAL and floating
  point, change results and are listed under *Changed*.

## On the wire

The IR and the catalog gain the composite type, the field access and the population flag, and
nothing else changes:

- `types.proto`: `TypeKind.TYPE_KIND_COMPOSITE = 19`, and `Type.fields = 6`, a composite's fields
  in declared order, each a name and a scalar type with its own nullability.
- `expr.proto`: `Expr.field_access = 12` and a new message, `FieldAccess`, whose `input = 1` is a
  composite and whose `index = 2` is a field's position in it. The expression is typed as the field,
  made nullable when the composite is. The comment on `KeySetMatch` now calls its key set
  row-valued; the message itself is unchanged.
- `catalog.proto`: `FunctionDescriptor.population = 15`, which `.Population()` sets.

The client and planner catalog validators accept a COMPOSITE only as a client-bodied function's
result or as a column of a local source's table. Every change is additive — new field numbers and a
new enum value, with nothing renumbered, renamed or removed — and the IR version is unchanged. A
planner run on its own host needs the 0.3 JAR for the composite type and the population flag;
`PlannerArtifact.CopyToAsync` exports the one that matches the installed client.

## Known limits

- A composite value is one level deep: a record inside a record, a list inside one and a list of
  records are refused.
- A composite value has no ordering and no equality. Sorting, grouping or partitioning by one,
  comparing one, `DISTINCT` over one, `CAST`ing one, joining on one and passing one to a built-in
  aggregate are refused; use one of its fields.
- A composite value is never a parameter or a table function's column, a SQL-bodied or native
  function cannot return one, and SQL cannot build one: `ROW(…)` is refused. `(f(x)).*` does not
  parse, so expand a composite through an alias (`s.c.*`), and read a field of an alias as
  `(c).field` or `s.c.field`.
- A composite column is read only from an in-process source, and a remote source that declares one
  is refused at registration. Nothing is keyed, indexed or ordered on a composite column or a field
  of one, it carries no statistics, and an Akade index keyed by the record is not an access path.
- Under entitlements a composite column is disclosed `Full` or `None`. `Masked`, `AggregateOnly` and
  `Test` are refused on one, as are a mask, a placeholder, an allow-list and the statistical opt-in.
- A DECIMAL wider than 28 digits has no Tier 1 spelling; a function over one is written as a Tier 2
  kernel.
- A span has no NULL, so a non-strict function's STRING parameter is `string?`, which allocates per
  row. A table function's producer is called once with boxed arguments, so its parameters cannot be
  spans.
- A plain Tier 1 aggregate answers a fixed-width value or a record; a STRING or BINARY answer needs
  an `ArenaAggregateSpec`. `ArenaScope.Return` frees nothing yet: a group's rented memory goes back
  when the operator releases, and a frame recomputed from its rows starts from an empty scope.
- `ArenaAggregateSpec`, `ArenaScope` and `ColumnWriter.Child` are experimental (`CHALK001`) and may
  change.
- A string-keyed `FrozenDictionary` takes an alternate key only under the runtime's own string
  comparers. A lookup by bytes into `string` keys needs a `Dictionary`, `HashSet` or
  `ConcurrentDictionary` built with `Utf8StringComparer.ForString`; a `FrozenDictionary` keyed by
  `Utf8String` works with `Utf8StringComparer.Ordinal`.
- A LIST has no ordering or equality either: `GROUP BY`, `SELECT DISTINCT`, a `DISTINCT` aggregate
  and `ORDER BY` over one are refused, and so is a LIST as a join key or a partition key.
- The standing limits hold: ChalkQL is read-only, and some correlated and `LATERAL` shapes are
  refused.
